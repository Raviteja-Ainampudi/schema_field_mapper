# MEMORY.md — durable agent notes

Append-only working memory for this project. Agents: add dated bullets; do not delete history unless correcting a factual error. Never store secrets here.

## Project facts

- Interview challenge: map MySQL `legacy_hrm` → MongoDB `people_platform` field-by-field.
- Critical constraint: cannot dump both full schemas into one LLM call for the complete mapping.
- Assignment source of truth: `InterviewAssignment.txt`.
- Local venv: `.venv` (Python 3.12). Platform-specific — run `scripts/setup_venv.ps1` (Windows) or `scripts/setup_venv.sh` (WSL/Linux) when switching OS. WSL Ubuntu 20.04 needs deadsnakes `python3.12`.

## Decisions

- 2026-08-11: Agent docs approach = `AGENTS.md` (stable rules) + `MEMORY.md` (living notes) + human `README.md`. No `.cursor/rules/` yet.
- 2026-08-11: Dual local environment. Windows venv for the day-to-day loop; WSL2 Ubuntu for Linux-parity checks (container build, Lambda RIE, case-sensitive filesystem) before deploying. A `.venv` is not portable between the two, so `scripts/setup_venv.ps1` and `scripts/setup_venv.sh` each replace a foreign venv rather than half-installing into it.
- 2026-08-11: Lambda constraints are centralized in `src/schema_mapper/config.py`, not scattered. Read-only assets resolve relative to the package (`ASSET_ROOT`), every write goes through `writable_dir()` which returns `/tmp/schema_mapper` when `AWS_LAMBDA_FUNCTION_NAME` is set. `.gitattributes` pins `eol=lf`.
- 2026-08-11: Confidence is a blend, not the model's self-report: `0.6 * model_confidence + 0.4 * normalized_retrieval_margin`, type-mismatch penalty, and a 0.85 cap when a required value transform is not mechanically expressible. Table confidence is the coverage-scaled mean of its fields. Pinned in `config.Thresholds`.
- 2026-08-11: Destination "fields" means leaf paths only (40 for this schema); container objects like `fullName` are never mapping targets. `type_transform` uses the ASCII `->` from the assignment's JSON example.
- 2026-08-11: Four accepted input formats so the same pipeline handles a pasted assignment snippet or a real dump: MySQL JSON, MySQL DDL, MongoDB JSON, MongoDB sample documents (Extended JSON). `data/samples/legacy_hrm.ddl.sql` exists as a parser fixture, not a migration script; no MySQL server is ever run.
- 2026-08-12: UI input is a first-class panel, not a buried tab. "Input data" is the first drawer tab and the header carries a dashed chip showing the parsed input (`database → database`, column and path counts, bundled vs edited) that opens it. Each side accepts paste, drag-and-drop, a file picker, or a bundled sample. `POST /api/parse` validates without a model call, so a bad format is caught before a paid run, and Run is disabled while the input does not parse.
- 2026-08-12: The destination parser accepted `fields`-list schemas but silently mis-read the **terse inline form** - `"fullName": {"firstName": "String"}` - as a single leaf named `fullName`, dropping both real paths. That is exactly the shape a reviewer gets by quoting the assignment's own Dataset B, so it was the most likely first input to fail. A JSON object is now a field spec only if it carries one of `name`/`type`/`bson_type`/`fields`/`comment`/`references`, and an inline sub-document otherwise; a trailing `-- comment` is kept and a `ref -> coll.path` comment becomes a reference. Pinned by `tests/test_terse_formats.py`, including parity with the bundled schema.
- 2026-08-12: Running `legacy_library` against `people_platform` completed successfully and paired `bk_master -> employees`. No stage was wrong: routing must pick *some* collection, shortlisting must offer *some* candidates, and unmatched fields are correctly declared unmapped. Nothing was positioned to ask whether the two schemas belong together, so a live run was spent on nonsense. Added `pairing.py` - a deterministic, model-free assessment surfaced in `POST /api/parse`, in the input panel, beside the run button, and in `run_report.json`.
- 2026-08-12: Calibrating that check taught the real lesson. My first metric - the fraction of source columns with *any* plausible destination - could not separate true pairs from crossed ones at all (true 0.789-0.971, crossed 0.421-0.794), because a crossed pair genuinely does place generic columns: `locations -> branches` scores 0.528 on its own merits since both really are addresses. Field-weighted **mean** affinity does separate (true 0.478-0.611, crossed 0.277-0.429). Two rules that fell out of this: score only vocabulary signals (lexical, fuzzy, comment) and drop type_compat and key_role, which are domain-blind and put a floor under every pair; and never flag a sub-pairing that is defensible on its own, or the warning trains the reader to ignore it. `scripts/eval_pairing.py` runs all 20 combinations and fails if any true pair scores below any crossed pair - the margin is only +0.049, which is exactly why this warns and never blocks.
- 2026-08-12: The terse-form fix above shipped with a second, subtler bug in the same spot, caught only by reading a live run's candidate list: `{"author": {"name": "String"}}` was read as a field spec because `name` is a spec key, collapsing `author.name` into a leaf called `author`. Two lessons. (1) `name`, `type`, and `comment` are spec keys *and* common leaf names, so key presence is too weak a test - an object is now a field spec only if **every** key is a spec key and at least one is not `name`. (2) The leaf **count** cannot detect this, since one leaf is replaced by one leaf; the structural invariant can - no real leaf is ever a prefix of another leaf. That invariant now runs over every bundled destination sample.
- 2026-08-12: A parser bug of this kind is worse than a wrong mapping: an invented path enters the candidate shortlist, so the model is asked to choose a destination that does not exist, and the hallucination guard cannot object because the path is in the (mis)parsed schema. When a live run produces a suspicious `destination_field`, check whether it appears in that field's `candidates` in the run report - if it does, suspect Stage 0, not the model.
- 2026-08-12: Docs are verified rather than asserted. `scripts/check_docs.sh` executes every example the docs promise against a running server and resolves every relative link, which already caught two wrong claims of mine (a miscounted leaf-path total and an endpoint that returns HTML). Treat a docs change as code: run it.
- 2026-08-12: System and workflow diagrams live in `docs/ARCHITECTURE.md` and `docs/PIPELINE.md` as Mermaid, with the two most useful ones repeated in `README.md`. Two checks guard them because they fail in different ways: `check_docs.sh` lints offline (unclosed fences, unknown diagram type, unbalanced block openers, unquoted brackets in flowchart labels) and `scripts/render_check_mermaid.py` posts each block to a real renderer, since only a renderer proves a diagram draws. `end` closes a `subgraph` in a flowchart but a `loop`/`alt`/`opt`/`par` in a sequence diagram, so the balance check has to be per diagram type.
- 2026-08-12: Verifying the renderer taught the lesson, not the diagrams. Two false verdicts in a row: mermaid.ink sits behind Cloudflare and answers the default urllib agent with `403 error 1010` (a block, not a syntax error), and every valid SVG it returns contains the string `error-text` in its stylesheet, so grepping the payload for error markers flagged all 12 diagrams as broken. A syntax error is an **HTTP 400** carrying the parse message. When a checker reports that everything is broken, suspect the checker: `--selftest` now renders two known-good and two known-broken diagrams and fails if it cannot tell them apart.
- 2026-08-12: An unmapped field had no explanation anywhere, which looked like the model returning nothing and was actually a serialization gap. `Decision.as_dict()` omitted `reasoning` and `notes`, and the UI reads reasoning from the artifact's `field_mappings` entry - which by definition does not exist for an unmapped field - so `emp_master.dob` showed an empty Reasoning row while a good sentence sat unused in `passes[]`. The report's `unmapped_source_explanations` had the same gap from the other side: it used `forced_null` (set only when the *pipeline* overrules the model) and fell back to boilerplate, so a deliberate decline never showed its reason. Precedence is now `forced_null` (names the mechanism) → `decision.reasoning` (the model's own words) → generic. The artifact contract is untouched: `unmapped_source_fields` stays a list of names, and explanations live in the run report.
- 2026-08-12: "Loading interface…" stayed visible below a fully working UI because `render(vnode, parent)` in Preact **appends** and does not clear the container, despite the comment in `index.html` claiming the placeholder was replaced on mount. `app.js` now clears the mount before rendering, and `check_ui.sh` fails if `index.html` has a boot placeholder that `app.js` never clears. Clearing in JS rather than deleting the placeholder is deliberate: it stays on screen while the module has not run, which is the failure it exists for.
- 2026-08-12: Mapping wires are drawn inside the middle canvas only, with X pinned to the canvas edges and Y measured from the real rows. Spanning the whole stage put the curves under the opaque schema columns, which read as a broken gap in the middle. Destination rows are also ordered to follow the source order of their wires, which turns crossing spaghetti into near-parallel runs.

## Experiments

- 2026-08-11: Bedrock access verified in `us-east-1` with `scripts/check_bedrock.py` (one-token Converse probe per model, since a model can be listed and still return `AccessDeniedException`). Usable: `us.anthropic.claude-sonnet-4-5-20250929-v1:0`, `us.anthropic.claude-haiku-4-5-20251001-v1:0`, `us.amazon.nova-lite-v1:0`, `us.amazon.nova-micro-v1:0`, `us.amazon.nova-pro-v1:0`. `list_foundation_models` returns 0 items for this account but 63 inference profiles are visible, so model IDs must use the `us.` inference-profile prefix.
- 2026-08-11: `us.anthropic.claude-sonnet-4-6-v1:0` does not exist (`ValidationException`). Claude 3.5/3.7 IDs return `ResourceNotFoundException` in this account. `.env` corrected to the Sonnet 4.5 ID.
- 2026-08-11: Embeddings left off by default (`ENABLE_EMBEDDINGS=false`). The deterministic scorer must reach 100% shortlist recall unaided; Titan is an optional accuracy assist, not a dependency.

- 2026-08-12: First full pipeline run works end to end. 33/34 source fields mapped, `dob` unmapped, contract + coverage validation pass, 11 LLM calls, ~$0.04 live. Offline cassette replay reproduces the artifact byte for byte apart from `generated_at`. Test suite: 245 passing.
- 2026-08-12: Stage 2 retrieval measures recall@6 = 100% **and rank@1 = 100%** on this schema pair (`scripts/eval_retrieval.py`). The deterministic scorer alone would pick every correct destination. Be honest about this in the write-up: the LLM's contribution here is the reasoning, the notes, the null decision on `dob`, and robustness on schemas where lexical signal is weaker - not the pairing itself. It is also the argument for the architecture: deterministic where deterministic is provably right, model where judgment is genuinely needed.
- 2026-08-12: Comment-to-name similarity turned out to be the strongest single non-obvious signal. `rec_stat` ("A=Active, I=Inactive, T=Terminated") reaches `employment.status` ("active / inactive / terminated") on comment agreement, and `dept_stat` reaches `isActive` only because the comment legend mentions "Active" while the identifiers share nothing.
- 2026-08-12: The cascade works as intended: Claude Haiku 4.5 answered every batch, and only `dob` (genuinely ambiguous) escalated to Sonnet 4.5. Escalation rate 3-6%.
- 2026-08-12: Retrieval scores are deliberately **not** shown to the model. If they were, the model would anchor on the top-ranked candidate and the blended confidence would be circular rather than two weakly-correlated signals.
- 2026-08-12: Reflection triggers on the *blended* confidence, not the model's self-report. A field the model is sure about that barely beat its runner-up is exactly what deserves a second look, and the raw self-report hides that.
- 2026-08-12: `type_transform` is rendered deterministically from the real types and is not requested from the model, which makes an impossible pairing like "VARCHAR -> Number" unrepresentable. Asserted by `test_constraint.py::test_no_response_contains_type_transforms`.
